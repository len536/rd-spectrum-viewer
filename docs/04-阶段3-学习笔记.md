## 1. 这一阶段到底解决了什么

阶段 1 的图：`plt.show()` 弹一个独立窗口，关掉就没了——它不是软件界面。
阶段 2 的窗口：能选文件，但选完只改了个标签，没有图。

阶段 3 把两者合起来：**窗口里有一块区域专门画图，点按钮选文件，这块区域就刷新成新数据的 RD 谱**。这才是老师要的「上位机软件界面」。

一句话记住三个新角色：

| 角色 | 是什么 | 类比 |
|---|---|---|
| `Figure` | 一张空白画布（数据 + 坐标系）+ | 画板 |
| `FigureCanvasQTAgg` | 把画板包装成 Qt 能显示的控件 | 把画板装进一个「窗口零件」，能塞进界面 |
| `NavigationToolbar2QT` | 平移/缩放/保存那排按钮 | 画板自带的工具条，手动挂上来 |

## 2. 逐段拆解 `rd_viewer.py`

### 2.1 后端设置必须在 import pyplot 之前（K3.1）

```python
import matplotlib
matplotlib.use("QtAgg")     # ← 必须在 import pyplot 之前
import matplotlib.pyplot as plt
```

- **为什么**：Matplotlib 的「后端」决定图往哪显示。`Agg` = 只存文件不弹窗（阶段 1 自动化用）；`tkagg` = 弹独立 Tk 窗口（本机默认）；`QtAgg` = 画进 Qt 控件——**只有它能为 `FigureCanvasQTAgg` 提供嵌入能力**。
- **顺序坑**：后端一旦被 pyplot 读过就定了，之后再 `use()` 没用。所以必须先 `use("QtAgg")` 再 `import pyplot`。
- 组会可以讲：「阶段 1 用 Agg 存图，阶段 3 换 QtAgg 嵌入，同一个库两种后端，切换只一行」。

### 2.2 面向对象 API：不碰 pyplot 全局状态（K3.2）

```python
self.fig = Figure(figsize=(7.2, 4.8), dpi=100)   # 直接造对象
self.canvas = FigureCanvasQTAgg(self.fig)        # 包装成 QWidget
```

- `plt.subplots()` 走的是 pyplot 的**全局状态**（"当前那张图" gcf），窗口程序里多张图/多线程容易串。
- `Figure(...)` 直接造一个独立对象，谁拿着谁负责，不依赖"当前"——这是 GUI 程序更稳的写法。
- `FigureCanvasQTAgg(fig)` 是桥梁：`Figure` 本身不是 Qt 控件，塞不进布局；canvas 既是 Matplotlib 的渲染面，又继承了 QWidget，所以 `outer.addWidget(self.canvas)` 能成立。
- 类比：`Figure` 是画的内容，`canvas` 是装画的相框——**相框是 QWidget，画不是**。

### 2.3 画布要能伸缩（K3.2 延伸）

```python
self.canvas.setSizePolicy(QSizePolicy.Policy.Expanding, QSizePolicy.Policy.Expanding)
```

不设的话画布保持固定像素，窗口拉大它不跟着变，四周留白。`Expanding` = 告诉布局「有富余空间就给我」。

### 2.4 嵌套布局（K3.4）

```python
outer = QVBoxLayout(central)
btn_row = QHBoxLayout()
btn_row.addWidget(self.open_btn)
btn_row.addWidget(self.file_label)
outer.addLayout(btn_row)     # ← 一行（横排）塞进竖排
outer.addWidget(self.toolbar)
outer.addWidget(self.canvas)
```

- 外层竖排三块：按钮行 / 工具栏 / 画布。
- 按钮行内部横排：按钮 + 标签。
- `addLayout` vs `addWidget`：塞的是「布局」用前者，塞的是「控件」用后者。这是布局嵌套的基本语法。

### 2.5 数据入口独立成模块（K3.3）

阶段 1 的 `load_rd()` 原本写在 `plot_rd_demo.py` 里。阶段 3 界面要复用，但直接 `from plot_rd_demo import load_rd` 会连带执行那个脚本顶部的 pyplot / rcParams 设置（import 模块会执行模块级代码）。

解决：把纯数据逻辑抽到 `01_backend/rd_data.py`，脚本和界面都从它 import：

```python
sys.path.insert(0, str(ROOT / "01_backend"))
from rd_data import load_rd
```

- `sys.path.insert(...)`：脚本运行时 Python 只在脚本所在目录找模块，`01_backend` 不在 `03_embed` 的搜索路径里，手动加进去。
- 这样「单一入口」（K1.17）从"一个函数"升级成"一个模块"：**真数据格式变了只改 `rd_data.py`，脚本和界面都不动**。组会讲风险控制就靠这条。

### 2.6 刷图核心 `_plot()`（K3.5 / K3.6 / K3.7）

```python
rd = load_rd(path)          # ① 读数据（复用单一入口）
self.fig.clear()             # ② 清空上一张图 ★
ax = self.fig.add_subplot(111)
im = ax.imshow(rd, cmap=CMAP, vmin=VMIN, vmax=VMAX,
               origin="lower", aspect="auto", interpolation="nearest")
cbar = self.fig.colorbar(im, ax=ax, ...)   # ③ 色条
...
self.canvas.draw()           # ④ 刷新 ★
```

三个关键点：

| 行 | 为什么 | 不这么做会怎样 |
|---|---|---|
| `fig.clear()` | colorbar 自己占一个 axes；不清，每选一次文件就多一条色条 | 选 5 次文件 → 5 条 colorbar 叠一起，图越来越挤 |
| `imshow(...)` 参数 | 和阶段 1 一字不差（jet / -50~0 / origin=lower / aspect=auto） | 保证「接近 MATLAB」风格连续，界面和脚本出图一致 |
| `canvas.draw()` | 界面的"刷新"动作，把 Figure 的改动重绘到控件上 | 数据读了、图画了，但屏幕不变——最常见的"为什么没反应" |

> 对比记忆：脚本里最后一步是 `fig.savefig()`（存盘），界面里是 `canvas.draw()`（重绘）。**同一张图，两种"输出"方式**。

### 2.7 启动就画默认数据（K3.8）

```python
self._plot(ROOT / "data" / "fake_rd.npy", startup=True)
```

- 好处：打开软件立刻看到图，不用先点按钮——演示友好。
- `startup=True` 是标记：启动时别改标签（保持"还没有选择文件"），因为这是默认数据，不是用户选的。
- **隐患留在阶段 4**：`data/` 被 gitignore，换电脑 clone 后没有 `fake_rd.npy`，这行会报 `FileNotFoundError`。阶段 4 接真数据时一并处理（默认无数据则显示空白提示）。这是诚实的技术债，组会被问到就直说。

### 2.8 槽函数与异常兜底（K2.5 / K3.9）

```python
try:
    self._plot(path)
except Exception as exc:
    self.statusBar().showMessage(f"读取失败: {exc}")
```

- 用户可能选了 `.csv`、图片、其他 `.npy`——`load_rd` 会抛异常。**不接住，整个软件就崩了**；接住，只在状态栏提示，窗口还在。
- 这是"能用的软件"和"能跑的脚本"的又一个区别：脚本崩了重跑，软件不能因为用户点错一下就退出。

## 3. 完整调用链（组会照着讲）

```
用户点「选择 RD 数据文件」按钮
  → clicked 信号（K2.5）触发 on_open_file 槽
  → QFileDialog 弹出系统选文件框，返回路径
  → _plot(path)：
        load_rd(path)         读成二维数组      [rd_data.py 单一入口]
        fig.clear()           清掉上一张图
        ax.imshow(...)        数值 → 颜色、按行列摆位（阶段 1 原理）
        fig.colorbar(...)     画色条
        canvas.draw()         ★ 刷到屏幕上
  → 标签显示文件名、状态栏显示完整路径
```

**阶段 1 的"数字查色摆位"原理一点没变**，变的只是输出从 `savefig()` 换成了 `canvas.draw()`。这就是分阶段开发的好处——底层逻辑复用，上层换壳。

## 4. 常见坑（现场验证过的）

| 现象 | 原因 | 修法 |
|---|---|---|
| 画布是空的 / 图不刷新 | 改了 Figure 但没调 `canvas.draw()` | 每次改图后必须 `draw()` |
| 选几次文件后色条叠了一堆 | 没清 axes，colorbar 每次新增一个 | `fig.clear()` 先清再画 |
| `FigureCanvasQTAgg` 塞不进布局或报错 | 后端还是 Agg/tkagg | `matplotlib.use("QtAgg")` 且放在 import pyplot 之前 |
| 换电脑打开就报 `FileNotFoundError` | `data/fake_rd.npy` 被 gitignore，没跟着走 | 阶段 4 处理；或先跑 `make_fake_rd.py` 造一份 |
| 窗口拉大画布不跟着变 | canvas 尺寸策略固定 | `setSizePolicy(Expanding, Expanding)` |

## 5. 自测题（阶段 3，6 题，不看答案作答）

1. `Figure` 和 `FigureCanvasQTAgg` 各是什么？为什么说"相框是 QWidget，画不是"？
2. 为什么 `matplotlib.use("QtAgg")` 必须写在 `import pyplot` 之前？阶段 1 用的什么后端？
3. 界面刷图最后一句为什么是 `canvas.draw()` 而不是 `fig.savefig()`？
4. `_plot()` 里 `fig.clear()` 不写会怎样？colorbar 有什么特殊之处导致必须清？
5. 为什么把 `load_rd()` 从 `plot_rd_demo.py` 抽到 `rd_data.py`？直接 import 绘图脚本有什么副作用？
6. 换一台电脑 clone 仓库后直接打开这个软件，最可能在哪一行报错？为什么？

<details>
<summary>答案（答完再展开）</summary>

1. `Figure` = 画布内容（数据+坐标系），本身不是 Qt 控件；`FigureCanvasQTAgg` = 把 Figure 包装成 QWidget 的桥梁，所以能 `addWidget` 进布局。类比：画 vs 装画的相框，相框能挂墙上（塞进界面），画不能。
2. 后端被 pyplot 第一次读取后就定死，之后再 `use()` 无效。阶段 1 自动化用 `Agg`（只存图不弹窗）；阶段 3 用 `QtAgg`（画进 Qt 控件）。
3. 脚本输出是存盘 png → `savefig()`；界面输出是让屏幕上的控件重绘 → `canvas.draw()`。同一张图两种输出方式。
4. colorbar 自己占一个 axes，`fig.clear()` 不清掉它，每选一次文件就多叠一条色条。所以重画前必须全清。
5. import 模块会执行模块级代码——直接 import `plot_rd_demo` 会连带跑它顶部的 pyplot/rcParams 设置，把绘图副作用带进界面。抽成 `rd_data.py` 只含纯数据逻辑，脚本和界面共用，且强化"单一入口"。
6. `self._plot(ROOT / "data" / "fake_rd.npy", ...)` 那行——`data/` 被 gitignore，新 clone 没有该文件，`np.load` 抛 `FileNotFoundError`。阶段 4 接真数据时处理（无默认数据就显示空白提示），或先跑 make_fake_rd.py 造一份。

</details>
