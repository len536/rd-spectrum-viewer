## 1. 先搞懂 RD 谱是什么（组会第一个问题）

雷达发出信号、接收回波。回波里藏着两件事：

| 维度 | 物理来源 | 大白话 | 怎么算出来（了解即可） |
|---|---|---|---|
| **距离维** | 回波回来得越晚，目标越远 | 「目标离我多远」 | 对快时间做 FFT |
| **多普勒维** | 目标相对运动 → 回波频率偏移 | 「目标朝我/背我跑多快」 | 对慢时间做 FFT |

合起来就是一张二维表：**行 = 距离门，列 = 多普勒通道，格子里 = 该(距离, 速度)处的回波功率**。

> 生活类比：把 RD 谱想成一张 Excel 表，横轴是"速度档位"、纵轴是"距离格子"，每个单元格填一个回波强度，然后**按数值大小涂颜色**——强的涂红、弱的涂蓝。所谓"画图"就是干这个。

```
        多普勒通道（速度）→
        0   8  16  24  32  40  48  56  63
距   0  .   .   .   .   █   .   .   .   .
离  30  .   .   ★   .   █   .   .   .   .
门  72  .   .   .   .   █   .   ★   .   .
↓  105  .   .   .   ★   █   .   .   .   .
   128  .   .   .   .   █   .   .   .   .
        ★ = 动目标（亮点）   █ = 零多普勒杂波带（竖着的一条）
```

**两个必须会讲的词**：
- **动态范围 / dB**：功率可能差几十万倍，直接画会糊成一片；取对数压成 -50 ~ 0 dB 才好显示。
- **零多普勒杂波**：地面、建筑物这些静止物速度≈0，会在"零速"那一列形成一条贯穿所有距离的亮带。这是真实 RD 图的标志，不加它，造出来的图一眼假。

> ⚠️ **诚实的边界**：FFT 的数学推导属于《信号与系统》，大二还没学。组会只需讲**物理含义**（上表前三列），老师追问就如实说"这块由算法组负责，我这边接收的是算好的二维矩阵"。别硬凹公式，反而露怯。

## 1.5 一句话版：数据是什么、作图原理是什么（2026-11-23 补讲）

**先立一个最容易错的认识：`fake_rd.npy` 里没有图片，只有一堆数字。**
它就是一张 128 行 × 64 列的数字表（`float32`，约 33 KB）：行 = 距离，列 = 速度，每个格子填一个回波功率（dB）。绝大多数格子 −45 上下（噪声），中间列 −8（静止物），个别格子 −3（动目标）。`.csv` 是同一堆数字的文本版（64 KB），人能打开看而已。

**作图原理只有三步，`imshow` 一次干完：**

| 步 | 干什么 | 代码里是谁 |
|---|---|---|
| ① 定尺子 | 规定「−50 涂深蓝、0 涂深红」，中间按数值插值 | `VMIN, VMAX = -50, 0` + `cmap="jet"` |
| ② 查色 | 每个格子的数字去尺子上比，取出对应颜色 | `cmap` 查表 |
| ③ 摆位 | 矩阵第 i 行第 j 列 → 图上第 i 行第 j 列（行=距离竖着放，列=速度横着放） | `ax.imshow(rd, ...)` |

`origin='lower'` / `aspect='auto'` 只管 ③ 怎么摆，与颜色无关；`colorbar` 只是把 ① 那把尺子画出来给人看；`savefig` 存盘。
串起来：**`load_rd()` 把数字读成二维数组 → `imshow` 逐格查尺子上色、按行列摆好 → colorbar 画尺 → savefig 存图。** 图是"渲染结果"，数据才是本体——所以换色表、换界面，数据一个字都不用动。

**为什么数据可以是伪造的**：作图代码只认"一张二维数字表"，不关心数字谁给的。真数据没到，先按真实结构（噪声底 + 零速列 + 动目标）造假的，把"读 → 画"链路跑通；接口确认后只换 `load_rd()` 内部实现。

## 2. `make_fake_rd.py` 逐段拆解

### 参数区（文件顶部常量）
`N_RANGE=128`（行）、`N_DOPPLER=64`（列）、`SEED`、`NOISE_FLOOR_DB=-45`、`TARGETS` 三元组。
**为什么把它们提到最上面**：改一个数 → 重跑 → 看图像怎么变，是理解代码最快的方式。这也是本阶段的动手作业。

### ① `rng.normal(NOISE_FLOOR_DB, NOISE_STD_DB, (N_RANGE, N_DOPPLER))`
一次生成整张 128×64 的噪声背景（均值 -45、标准差 2 的正态分布）。
- **为什么用 `default_rng(SEED)` 而不是 `np.random.seed`**：前者是现代写法，且固定种子保证**每次跑出来一模一样** —— 组会 PPT 里的截图不会和现场演示对不上。
- 改 `NOISE_STD_DB` 变大 → 背景更"花"；改 `NOISE_FLOOR_DB` 变大 → 整张图变亮、弱目标被淹没。

### ② `np.meshgrid(..., indexing="xy")`
把「列的编号」和「行的编号」摊成两个 128×64 的矩阵：`d_grid[i,j]=j`（多普勒索引）、`r_grid[i,j]=i`（距离索引）。
- **为什么需要**：后面要对整个矩阵一次性算高斯，才能用 NumPy 的**向量化**（不用写两层 for 循环，快几十倍）。
- `indexing="xy"` 保证输出形状是 `(N_RANGE, N_DOPPLER)`，和 `rd` 对得上；换成 `"ij"` 会转置，图就横竖颠倒。

### ③ 目标亮斑（二维高斯）
```python
shape = np.exp(-(((d_grid-d0)**2)/(2*sd**2) + ((r_grid-r0)**2)/(2*sr**2)))
```
中心=1、越远越接近 0 的"钟形包"，用来近似点目标经 FFT 后的主瓣。
- **为什么乘 `contrast` 再用 `np.maximum`，而不是直接 `rd += 目标`**：
  `contrast = peak - 噪声底`，中心处恰好等于目标峰值 dB，远处回到噪声底；`maximum` 让"亮的地方盖住背景、暗处不扰动噪声"，符合"该处功率被目标主导"的物理情形。若用 `+=`，峰值会变成 `-45 + (-3) = -48`（反而更暗），而且会叠加出不合理数值。
- 改 `sr/sd` → 亮斑变胖变瘦；改 `peak` → 亮斑变亮变暗。

### ④ 零多普勒杂波
`d_zero = N_DOPPLER // 2 = 32`：FFT 之后通常做了 `fftshift`，**零速落在中心列**。用只在 `d_grid` 方向衰减的高斯，得到一条贯穿所有距离门的竖亮带。
- **一个超实用的自检技巧**：出图后看杂波带是不是**竖着**的。如果横着了，说明两维搞反了，需要 `.T` 转置。组会前一定这么验一次。

### 保存与 `main()`
- `.npy`：NumPy 二进制，保 `dtype`、读写最快 → 画图脚本读它。
- `.csv`：`np.savetxt` 文本格式，通用但体积大、丢精度 → 只是让你见见"另一种格式长啥样"，因为真实接口还没定。
- `astype(np.float32)`：功率精度够用，比 float64 省一半内存（阶段 4 大矩阵时很重要）。
- `if __name__ == "__main__":`：**直接运行**这个文件时才执行 `main()`；以后被别的模块 `import` 时不会乱跑。这是 Python 模块的标准写法。

## 3. `plot_rd_demo.py` 逐段拆解

### ★ 最重要的设计：`load_rd()` 单一入口
它只干一件事：**文件 → 二维 float 数组**，并顺手 `assert ndim == 2` + 打印 shape/范围。
现在读 `.npy`；以后真数据来了（txt/csv/mat/Socket），**只改这个函数内部**，返回同样形状的矩阵就行。`plot_rd()` 和阶段 2-3 的界面代码一行都不用动。
→ 这就是「接口没定也能开工」的底气，也是组会讲**风险控制**的核心（K1.17）。

### ① `rcParams` 全局样式
| 设置 | 不设会怎样 |
|---|---|
| `font.sans-serif = ["Microsoft YaHei", ...]` | 中文标题变成一堆方框 □□□ |
| `axes.unicode_minus = False` | 负号 `-45` 变成小方块 |
| `xtick/ytick.direction = "in"` | 刻度朝外，不像 MATLAB |
| `font.size = 11` | 字号不统一 |

### ② 显示参数
`VMIN/VMAX = -50/0` 是**显示动态范围**（对应 MATLAB 的 `caxis`），`CMAP="jet"`，`DPI_SAVE=300`（存进 PPT 才不糊）。

### ③ `fig, ax = plt.subplots(...)`
**面向对象写法**：`fig` 是整张画布，`ax` 是坐标系。
- 为什么不用 `plt.imshow(...)` 这种全局写法：阶段 3 要把画布塞进 Qt 窗口，用的是 `FigureCanvasQTAgg(fig)` —— 手里得有 `fig` 这个对象。从现在起养成习惯，后面零改动。
- `plot_rd()` 被写成**独立函数且带参数**，就是为了阶段 3 原样复用。

### ④ `ax.imshow(...)` 六个参数逐个说
| 参数 | 作用 | 改了/删了会怎样 |
|---|---|---|
| `rd` | 矩阵本身；第 0 轴自动落在 **y 轴** → 正好 y=距离 | 传 `rd.T` 会横竖颠倒（用竖亮带自检） |
| `cmap` | 数值→颜色映射表 | `jet` → 老 MATLAB 味；`viridis` → 科学但"不像 MATLAB" |
| `vmin/vmax` | 颜色条两端的数值 | 设 `-30` 会把 -45 的噪声全压成同一深色，弱目标信息丢失 |
| `origin="lower"` | 第 0 行画在**下方** | 默认 `upper` 会让距离方向倒过来；等价 MATLAB `axis xy` |
| `aspect="auto"` | 不强制格子为正方形 | 默认 `equal` 会把 128×64 压成一条狭长带（两维量纲不同，不能等比例） |
| `interpolation="nearest"` | 不插值模糊 | 默认会插值，格子边界糊掉，MATLAB `imagesc` 是清晰方块 |

### ⑤ `fig.colorbar(...)`
颜色与数值的**对照尺**，没有它老师看不出红色到底是多少 dB。`fraction/pad` 调的是它和主图的宽度、间距（纯美观）。

### ⑥ 坐标轴
现在用 bin 索引，因为**标定信息还没问到**。等接口确认拿到"每距离门多少米 / 每通道多少 m/s"，就在 `imshow` 里加 `extent=[d_min,d_max,r_min,r_max]`，坐标轴直接变成物理量（K1.18，呼应接口清单第 4 问）。

### ⑦ 先 `savefig` 再 `show`
`plt.show()` 之后 figure 可能被释放，先 show 会存到空图。`matplotlib.get_backend()` 判断是不是 Agg（无界面后端，自动化跑脚本时不弹窗）—— 对应知识点 K1.15。

## 4. MATLAB ↔ Python 对照表（组会直接放这页）

| MATLAB | 本项目 Python | 备注 |
|---|---|---|
| `imagesc(rd)` | `ax.imshow(rd, ...)` | 都是按格子涂色 |
| `colormap jet` | `cmap="jet"` | 老 MATLAB 默认 |
| `colorbar` | `fig.colorbar(im, ax=ax)` | 颜色尺 |
| `caxis([-50 0])` | `vmin=-50, vmax=0` | 显示动态范围 |
| `axis xy` | `origin="lower"` | y 轴向上增大 |
| `xlabel / ylabel / title` | `ax.set_xlabel / set_ylabel / set_title` | |
| `set(gca,'FontSize',11)` | `plt.rcParams["font.size"]=11` | 全局设置 |
| `set(gca,'TickDir','in')` | `xtick/ytick.direction="in"` | 刻度朝内 |

## 5. 进阶：注册 MATLAB 的 parula 色表（选做）

from matplotlib.colors import LinearSegmentedColormap
anchors = ["#352a87", "#0f5cdd", "#10a8e0", "#5eb3a3",
           "#a7d04b", "#e8b23a", "#e5632a", "#a42423"]
parula = LinearSegmentedColormap.from_list("parula", anchors)
# 把 plot_rd 的 CMAP 换成 parula 即可

## 6. 常见坑清单

| 现象 | 原因 | 修 |
|---|---|---|
| 中文全变方框 | 没设 `font.sans-serif` | ① |
| 负号变方块 | 没设 `axes.unicode_minus` | ① |

### 现场案例（2026-11-23，第一次跑脚本就踩到）

VS Code 的 ▶ 按钮实际执行的是：

```bash
python -u "d:\...\01_backend\plot_rd_demo.py"
```

`-u` = unbuffered（让 `print` 立即输出、不被缓存），后面是脚本全路径。**坑在开头那个 `python`**：它指的是 VS Code 当前选中的解释器，不是我们项目的 `.venv`。
`make_fake_rd.py` 只用 numpy，而那个全局 Python 恰好装过 numpy → 跑通了；`plot_rd_demo.py` 要 matplotlib，它没装 → 第 17 行 `import matplotlib` 就炸了。

验证当前解释器到底是谁：

```bash
.venv\Scripts\python.exe -c "import sys, matplotlib; print(sys.executable, matplotlib.__version__)"
```

能打印出 `.venv` 路径和版本号，就说明用对了。

## 9. 自测题答案（做完第 7 节再看）

1. 全局只有一个 site-packages，不同项目依赖版本会冲突（A 要 numpy 1.x、B 要 2.x）；venv 给每个项目独立环境，删了重建成本极低，换电脑能复现。
2. 记录依赖及版本，`pip install -r` 一键复现。分阶段注释：依赖随阶段演进可追溯、报错时能定位是哪个包引入的、阶段 1 不必下载 150MB 的 PySide6。
3. `.venv` 体积大且可重建；`data/` 运行时可重造、真实数据大且可能涉密；`docs/images/` 是成果证据，必须 commit 进仓库供组会展示。
4. 工作区 →（`git add`）暂存区 →（`git commit`）本地仓库。一个阶段一个 commit 让 `git log` 成为研发时间线，能回溯每步做了什么，直接给老师看过程。
5. 本机 HTTPS 直连 github.com 实测连接被重置，但 SSH 认证成功（`Hi len536!`），所以远程地址用 `git@github.com:len536/...`。
6. ① PySide6 是 Qt 官方绑定、LGPL 许可，闭源/交付无法律风险；PyQt5 是第三方 GPL/商业双许可，交付有隐患。② API 几乎一致，PyQt5 教程通用，学习成本不增加。③ 与后续 UAV 地面站项目技术栈统一。（任说两条）
7. 上位机是跑在 PC 上的显控软件：把下位机（雷达/飞控/单片机）采集或算好的数据展示给人、并下发指令。本项目里算法组给 RD 矩阵，我负责显示。
8. 行 = 距离门（多远），列 = 多普勒通道（多快），值 = 该(距离,速度)单元的回波功率（dB）。
9. 功率动态范围极大，取对数压到 -50~0 才好着色。`vmin/vmax` 是 colorbar 两端，决定颜色映射区间：超出会饱和成同一颜色；设太窄丢弱目标、太宽丢对比度。
10. 静止地物速度≈0，在零速列形成贯穿各距离的亮带，是真实 RD 图的标志；加了才像真的，还能用来**自检矩阵方向**（亮带必须竖着）。
11. `origin='lower'` 让第 0 行在下方、y 轴向上（↔ MATLAB `axis xy`），默认 `upper` 会把距离倒过来；`aspect='auto'` 允许两维格子不等宽，默认 `equal` 会把 128×64 压成细长条。
12. jet 色表 / colorbar / 刻度朝内 / `origin='lower'` / `vmin-vmax` 对应 caxis / `interpolation='nearest'` 保留方块感 / 完整坐标标签字号。（任说 3 处）
13. 因为「文件→矩阵」被收敛到 `load_rd()` 单一入口，绘图只认"二维 float 数组"这个抽象，不关心数据从哪来；接口定了只改这一处，绘图与界面代码不动。即关注点分离 / 面向接口编程，也是接口未定风险下的应对。
14. jet = 老 MATLAB 默认彩虹色，亮度不单调但"一眼 MATLAB"；parula = MATLAB R2014b 后的新默认、感知更均匀，matplotlib 没内置需自行注册；viridis = matplotlib 默认、感知均匀且色盲友好，但视觉上不像 MATLAB。老师要求接近 MATLAB → 选 jet。
