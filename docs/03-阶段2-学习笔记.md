## 1. 先搞懂：脚本和窗口程序是两种东西（K2.8）

阶段 1 的程序：从上往下跑 → 存图 → 结束。像**洗一件衣服**：放进机器，等它洗完，完事。

阶段 2 的程序：启动 → **停在那儿等你点** → 你点一下它动一下 → 你关窗它才结束。像**开一家店**：门开了，店员站着等客人，来一个接待一个，打烊才走。

| | 阶段 1 脚本 | 阶段 2 窗口程序 |
|---|---|---|
| 执行方式 | 顺序执行，跑完退出 | 事件驱动，一直等事件 |
| 谁决定下一步 | 代码写死的顺序 | **用户**点哪里 |
| 结束条件 | 最后一行跑完 | 用户关窗口 |
| 代码体现 | `plot_rd_demo.py` 从上到下 | `app.exec()` 进入事件循环，卡在那儿不返回 |

一句话背下来：**事件循环就是一个「等客人」的死循环，Qt 帮你写好了，你只负责告诉它「客人来了叫谁」。**

## 2. 骨架逐段拆解

### 2.1 `main()`：程序的入口（K2.1）

```python
app = QApplication(sys.argv)   # ① 造应用对象，一个进程只能有一个
window = MainWindow()          # ② 造窗口
window.show()                  # ③ 显示；不写这行窗口不会出现在屏幕上
sys.exit(app.exec())           # ④ 进入事件循环；关窗后 exec() 返回，程序才退
```

- 为什么必须有 `QApplication`？它是 Qt 的「大总管」：管鼠标键盘事件、管字体、管整个程序的生命周期。没有它，控件造不出来。
- `exec()` 为什么让程序不结束？因为它内部是个循环，不停地问系统「有事件吗？有就分发给对应控件」。你关窗 → 它收到关闭事件 → 循环结束 → 返回。
- `sys.exit(...)` 把 `exec()` 的返回值交给操作系统，表示程序正常退出。

### 2.2 `class MainWindow(QMainWindow)`：窗口类（K2.2）

- `QMainWindow` 是「带菜单/状态栏的标准主窗口」；`QWidget` 是所有控件的老祖宗。
- `super().__init__()` 必须先调——父类要在内部建一堆状态，不调后面 `setWindowTitle` 之类可能出错。
- `setCentralWidget(central)`：**主窗口中间那块地必须放一个控件**，布局挂它上面。没它的话 `setLayout` 无处安放，控件显示不出来。这是新手最常见的空白窗口原因。

### 2.3 TODO 1：布局（K2.3 + K2.7）

为什么不用 `label.move(10, 20)` 手写坐标？

- 手写坐标是「钉死位置」，窗口一拉大，控件还挤在左上角，右边全空；换分辨率直接乱。
- 布局管理器是「自动排班」：`QVBoxLayout` 竖着排，`QHBoxLayout` 横着排，窗口一变它自动重算。

`QVBoxLayout(central)` 括号里传 `central` 叫「认父」（K2.7）：控件归父对象管，父对象销毁时子对象一起没，不用手动删。你 `addWidget` 时布局也会自动把控件挂到父对象下。

**阶梯提示**（先看①，卡住再看②）：
1. 需要三行：造布局、加标签、加按钮。最后不用 `central.setLayout(layout)`，因为 `QVBoxLayout(central)` 已经挂好了。
2. 想验证布局生效：窗口拉大，标签和按钮应该跟着重新排布，而不是一个在左上、一个钉在别处。

### 2.4 TODO 2：信号与槽（K2.5）

这是整个 Qt 最核心的机制，也是组会必问：

- **信号（signal）**：控件发出的「我出事了」通知。`self.button.clicked` 就是「我被点了」这个信号。
- **槽（slot）**：你写的、要被调用的函数。这里就是 `self.on_open_file`。
- **连接（connect）**：把两者绑起来。`clicked.connect(on_open_file)` = 「这按钮一被点，就去叫这个函数」。

为什么不用 `while True` 一直检查「按钮被点了吗」？那样 CPU 100% 空转，还错过快速点击。事件循环 + 信号槽是「有事叫我，没事我睡觉」，效率高、代码清晰。

**最大的坑**：`connect(self.on_open_file)` 传的是函数本身；写 `connect(self.on_open_file())` 会在连接那一刻就执行它，然后连了个 `None`——以后点击完全没反应，还不报错。

**阶梯提示**：
1. 一行搞定：`self.button.clicked.<某个方法>(self.on_open_file)`。方法名就是「连接」的英文。

### 2.5 TODO 3：槽函数（K2.4 + K2.6）

槽函数就是普通函数，只不过是被信号「自动调用」的，所以也叫回调。它的三件事对应三种 Qt 能力：

| 步骤 | 用到的东西 | 掌握标准 |
|---|---|---|
| ① 弹选文件框 | `QFileDialog.getOpenFileName(self, "标题")` | 知道返回的是 `(路径, 过滤器)` **元组**，要用两个变量接 |
| ② 更新标签 | `self.label.setText(...)` | 知道控件的文字是用 `setText` 改的，不是重新造一个 |
| ③ 更新状态栏 | `self.statusBar().showMessage(...)` | 知道状态栏是 `QMainWindow` 自带的，一句话取 |

**阶梯提示**（逐级看）：
1. 先只写①，跑一下：点按钮能不能弹出系统选文件框？能，说明连接成功了。
2. 再加②：选完文件，标签文字变没变？没变就检查 `setText` 传的是不是字符串。
3. 最后加③：状态栏给个反馈，比如 `"已选择: xxx"`。
4. 用户点了「取消」怎么办？`getOpenFileName` 返回空字符串 —— 这时别 `setText("")`，给个「已取消」的提示更友好。这是加分项，不是必须。

## 3. 阶段 2 自测题（不看答案能答出来才算过）

1. 为什么 Qt 程序必须调用 `app.exec()`？直接 `window.show()` 然后结束会怎样？
2. `QMainWindow` 为什么要有 central widget？
3. `QVBoxLayout` 和手写 `move(x, y)` 比，好处是什么？
4. 「信号」和「槽」分别是什么？`connect` 那一行为什么不能写成 `connect(fn())`？
5. `QFileDialog.getOpenFileName()` 返回什么？怎么只显示文件名？
6. 阶段 1 的 `load_rd()` 和阶段 2 的窗口，谁调用谁？点一次按钮触发什么链路？

<details>
<summary>答案（答完再展开）</summary>

1. `exec()` 进入事件循环，程序停在里面等事件；不调用则窗口一闪而过或直接退出，没法交互。关窗后 `exec()` 返回。
2. 主窗口中央区域必须有一个控件作为布局的容器；没有它控件无处安放，窗口会空白。
3. 自动重排，窗口缩放/分辨率变化不会乱；代码更少更稳。
4. 信号=控件发出的「出事了」通知，槽=被自动调用的函数；`fn()` 会立即执行并把返回值（`None`）连上去，点击时就没反应了。
5. 返回 `(路径字符串, 过滤器字符串)` 元组；`Path(路径).name` 取文件名。
6. 阶段 2 窗口是「壳」，`load_rd()` 是被槽函数调用的「活」；点按钮 → 信号 → 槽 → 选文件 → （阶段 3 才）读数据画图。阶段 2 先不画图，只把「点按钮有反应」链路打通。

</details>
