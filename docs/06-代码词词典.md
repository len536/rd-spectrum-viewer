# 代码词词典 · 每个英文词拆开讲

> 为什么有这份文件：负责人明确要求「代码里的词看不懂就学不踏实」。
> 这份词典把项目里出现的**每个英文标识符 / 参数 / 术语**拆到词根，讲清「字面意思 → 在这里干嘛 → 改了会怎样」。
> 用法：看到不懂的词，`Ctrl+F` 搜它。不要求背，要求**查得到、讲得出**。
> 判定：能讲 = ✅；半懂 = 🟡；不懂 = ❌，回来问。

---

## 0. 先学会「拆词」这件事本身

英文技术词看着吓人，其实大多能拆成好几块，每块都有意思：

| 词 | 拆开 | 字面意思 | 合起来 |
|---|---|---|---|
| `cmap` | c + map | c = color（颜色）的缩写；map = 映射 | **颜色映射表**：一张「数字→颜色」的对照表 |
| `imshow` | image + show | 图像 + 显示 | 把矩阵当图像显示出来 |
| `colorbar` | color + bar | 颜色 + 条 | 颜色对照尺（那条渐变色带） |
| `numpy` | numerical + python | 数值的 + Python | 做数值计算的库 |
| `matplotlib` | math + plot + lib | 数学 + 绘图 + 库 | 画图的库 |
| `ndim` | n + dimension | n = 几；dimension = 维度 | 数组是几维的 |
| `dtype` | data + type | 数据 + 类型 | 数组里每个数是什么类型 |
| `vmin` / `vmax` | value + min / max | 数值 + 最小 / 最大 | 颜色尺两端对应的数值 |

**核心一招**：看到 `-` 或驼峰（小写接大写，如 `addWidget`）就当成一个新词的分界；先猜每块的意思，再合起来。猜错了没关系，猜过一遍再查，记得最牢。

> ⚠️ 易错点：`map` 在这里**不是「地图」**，是数学的「映射」——给一个输入，按规则对应到一个输出。就像查字典：给一个单词，查到它的解释。这里给一个 dB 数字，查到一种颜色。

## 1. 数据与绘图（阶段 1）

| 词 | 拆开 / 字面 | 在这里干嘛 | 改了 / 删了会怎样 |
|---|---|---|---|
| `load_rd` | load + RD | 读取数据；RD = Range-Doppler（距离-多普勒） | 唯一数据入口，接口变了只改这里 |

| `.min()` / `.max()` | 最小 / 最大 | 数组里最小 / 最大的数 | 打印出来看功率范围 -45 ~ -3 |
| `meshgrid` | mesh + grid | 网格 + 格点：造两张二维坐标表 | 改斜带那题就靠它；不懂它别想改坐标 |
| `np.exp` | exponential | 指数函数 e^x | 造杂波带的高斯形状 `exp(-(d-d0)²/(2σ²))` |
| `np.random` | random | 随机数 | 造噪声底；`seed` 固定种子才能每次一样 |

| `viridis` | 拉丁语「绿」 | matplotlib 默认色表：紫→蓝→绿→黄 | 感知均匀、色盲友好，但不像 MATLAB |

| `set_xlabel` / `set_ylabel` | set + label | 设置 x / y 轴文字 | 标注物理意义（多普勒通道 / 距离门） |

## 2. 界面与事件（阶段 2）

| 词 | 拆开 / 字面 | 在这里干嘛 | 改了 / 删了会怎样 |
|---|---|---|---|
| `QApplication` | Qt + application | Qt 程序的「应用对象」，管整个程序 | 每个 Qt 程序必须有且只有一个 |
| `exec()` | execute 的缩写 | 进入事件循环，程序「一直等」 | 不调它窗口一闪就退；它是「关窗才结束」的原因 |
| `QMainWindow` | Qt + main + window | 主窗口（带状态栏的那种） | 我们窗口的父类 |
| `QWidget` | Qt + widget | 所有界面控件的老祖宗 | 按钮、标签、画布都是它的子类 |
| `setCentralWidget` | central + widget | 设置窗口中间的「中央控件」 | 不设它，往窗口里塞东西不显示 |
| `QVBoxLayout` | V = Vertical（竖直）+ box + layout | 控件竖着排队 | 不设布局，控件叠在左上角 |
| `QHBoxLayout` | H = Horizontal（水平） | 控件横着排队 | 按钮 + 标签那一行用它 |
| `addWidget` | add + widget | 往布局里加一个控件 | 加的顺序 = 显示顺序（先加在上/左） |
| `addLayout` | add + layout | 往布局里再套一个布局 | 实现「一行里排俩」的嵌套 |
| `QPushButton` | push + button | 按钮（按下去那种） | |
| `QLabel` | label | 文字标签 | 显示选中的文件名 |
| `setText` | set + text | 改控件的文字 | 标签更新就靠它 |
| `clicked` | click 的过去式 | 按钮发出的「我被点了」信号 | |
| `connect` | 连接 | 把信号登记到某个函数上 | `按钮.clicked.connect(函数)`；函数**不加括号** |
| `slot` | 槽 | 被信号调用的那个函数 | 我们的 `on_open_file` 就是槽 |
| `QFileDialog` | file + dialog | 系统文件选择框 | |
| `getOpenFileName` | get + open + file + name | 弹框选文件，返回文件路径 | 返回的是 `(路径, 过滤器)`；点取消 → 路径是空字符串 |
| `statusBar` | status + bar | 窗口底部状态栏 | `showMessage` 在它上面写提示 |
| `showMessage` | show + message | 显示一条状态信息 | |
| `Path` | 路径 | `pathlib` 库里表示文件路径的对象 | `Path(p).name` 从完整路径里只取文件名 |
| `super().__init__()` | super = 父类 | 调用父类的初始化 | 写界面类第一行几乎必有它 |
| `self` | 自己 | 实例对象自己；`self.x` = 「我的 x」 | 类里访问自己的属性都要加 `self.` |

## 3. 嵌入与刷新（阶段 3）

| 词 | 拆开 / 字面 | 在这里干嘛 | 改了 / 删了会怎样 |
|---|---|---|---|
| `FigureCanvasQTAgg` | Figure + canvas + Qt + Agg | 把 Figure 包装成**能塞进 Qt 布局的控件** | canvas 是 QWidget 才能 `addWidget`；相框是控件，画不是 |
| `NavigationToolbar2QT` | navigation + toolbar | 导航工具栏（复位/平移/缩放/保存） | 阶段 1 弹窗自带的那排，这里手动挂上 |
| `matplotlib.use` | use = 使用 | 指定绘图后端 | `QtAgg` 才能嵌 Qt；`Agg` 是无界面存图；必须在 `import pyplot` **之前** |
| `QtAgg` | Qt + Anti-Grain Geometry | 用 Qt 画图的后端 | 后端一旦被读就定死，改晚了没用 |
| `add_subplot(111)` | add + subplot | 在 Figure 上加一个子图；111=1行1列第1个 | |
| `fig.clear()` | clear = 清空 | 刷新前清空上一张图 | 不清 → colorbar 每选一次文件多叠一条 |
| `canvas.draw()` | draw = 画 | 把 Figure 的改动重绘到控件上 | **界面的「刷新」就是它**；对应脚本的 `savefig()` |
| `setSizePolicy` | size + policy | 控件如何随窗口伸缩 | `Expanding` = 跟着窗口变大 |
| `QSizePolicy.Policy.Expanding` | expanding = 扩张 | 伸缩策略：尽量占满 | 不设它画布保持固定像素，窗口拉大留白 |
| `try / except / else` | 尝试 / 捕获 / 否则 | 异常处理：出错不让软件崩 | 选到非 `.npy` 文件 → 状态栏报「读取失败」而不是闪退 |
| `Exception` | 异常 | 所有错误的父类 | `except Exception as exc` 兜住任何错；`exc` 是错误对象 |
| `f"..."` | f-string | 字符串里嵌变量：`{path}` 会被替换成变量值 | 阶段 1 讲过，这里用来拼「已显示: 路径」 |
| `startup` | start + up | 启动标志 | `True` 时启动画默认图，但不改文件名标签 |

## 3.5 多格式与多线程（阶段 4）

| 词 | 拆开 / 字面 | 在这里干嘛 | 改了 / 删了会怎样 |
|---|---|---|---|
| `suffix` | suf + fix | 文件名后缀（`.npy` / `.csv`） | `path.suffix` 拿到它，决定用哪个读取函数 |
| `loadtxt` | load + txt | 读文本表格 | csv/txt 用它；`delimiter=","` 指定逗号分隔 |
| `delimiter` | de + limit + er | 分隔符 | csv 是逗号；制表符文件要改成 `\t` |
| `loadmat` | load + mat | 读 MATLAB .mat | 返回字典，按变量名取值 |
| `scipy` | scientific + python | 科学计算库 | 只在读 .mat 时按需 import |
| `ndim` | n + dimension | 数组是几维 | `if rd.ndim != 2` 是最快的接口自检 |
| `.T` | transpose | 转置（行列互换） | 两维搞反时用 `rd.T` 翻过来 |
| `to_db` | to + db | 转成 dB 单位 | 线性功率/IQ 按公式换算；db 原样返回 |
| `log10` | log + 10 | 以 10 为底的对数 | dB = 10×log10(功率) |
| `QThread` | Qt + thread | Qt 工作线程 | 耗时读文件放这里，界面不卡 |
| `Signal` | 信号 | 线程间传消息的信使 | `loaded = Signal(object)` 传数组；`failed = Signal(str)` 传错误 |
| `emit` | 发出 | 发信号 | `self.loaded.emit(rd)` 把数据寄回主线程 |
| `worker` | 干活的人 | 在后台干活的对象 | `self.worker = LoadWorker(path)` 存住它别被回收 |
| `run()` | 运行 | QThread 里真正干活的函数 | 自动被 `start()` 触发；**不能碰 UI** |
| `start()` | 开始 | 启动线程 | 调它才会执行 run() |
| `wait()` | 等待 | 等线程干完 | 测试里用；界面里不能用（会把主线程也卡住） |
| `finished` | 完成 | 线程结束自动发的信号 | 用它恢复按钮状态 |
| `setEnabled(False)` | enable + False | 禁用控件 | 读文件中禁用按钮，防连点开一堆线程 |
| `isRunning()` | 是否运行中 | 查询线程状态 | 测试里确认线程已结束 |
| `QEventLoop` | event + loop | 事件循环（测试专用） | 让跨线程信号有机会被投递；界面里是 `app.exec()` |
| `RuntimeError` | runtime + error | 运行时错误 | 没装 scipy 时抛它，给友好提示 |
| `try / except / else` | 尝试/捕获/否则 | 异常处理 | 读失败走 except，成功走 else；不让软件崩 |
| `import`（函数内） | 导入 | 在需要时才加载库 | scipy 放函数里 = 按需依赖，不用时不装 |

## 3.6 实操：一行代码怎么读（负责人 11-24 卡在线程词和多格式函数后补）

> 词列出来了还是看不懂？因为词是散的、代码是串的。这节教「把一行英文读成人话」的套路。

### 万能读法：`A.动作(材料)` = 对 A 做这个动作，材料是括号里的东西

看任何一行，先找**动作词**（connect / emit / start / load / setText…），其余是「谁」和「用什么」。

### ① 线程四行 = 一条送菜链（对应 B 类困惑）

生活类比：**主线程 = 前厅服务员**（负责接待、上菜 = 响应点击、画图）；**工作线程 = 后厨厨师**（只管闷头读文件）。

| 代码（看着吓人） | 拆开读 | 人话 |
|---|---|---|
| `loaded = Signal(object)` | Signal=信号；object=任意对象 | 定义一只「铃」，铃能装一个数组传过来 |
| `loaded.connect(_on_loaded)` | connect=登记 | 提前说好：铃一响就叫 `_on_loaded` 去画图 |
| `worker.start()` | start=开工 | 让后厨开工，开工才会执行 `run()` |
| `loaded.emit(rd)` | emit=发出 | 厨师按铃：把读好的数组 rd 寄回主线程 |

四个词一次性记牢：**worker=干活的人 / start=让他开工 / emit=按铃寄数据 / connect=登记铃响了叫谁**。
一句话记住分工：**QThread 不是让读文件变快，是让界面读文件时还能响应。**

### ② 多格式那堆 `_load_xxx` = 分拣台（对应 C 类困惑）

看着一堆函数晕，其实是**分拣**：看后缀 → 选工具 → 都交出同一张表。

| 你看到的 | 其实是 |
|---|---|
| `suffix = path.suffix.lower()` | 看文件名后缀（`.npy`/`.csv`/`.mat`），`.lower()` 让 `.NPY` 也认得 |
| `if suffix == ".npy": ... elif ...` | 分拣：不同后缀走不同货架；新增格式 = 加一个 `elif` 分支 |
| `_load_npy` / `_load_text` / `_load_mat` | 三个「专用读取工」，每个只认一种格式，别被名字数量吓到 |
| `return rd`（都在末尾） | 不管走哪条路，交出来的都是**同一张二维数字表**——所以画图那句永远不用改 |

关键洞察：**这一堆函数存在的意义，是让外面的画图/界面代码不用关心数据是什么格式。** 这叫「封装」——里面怎么变，外面不动。

### ③ 下次遇到看不懂的代码，三步走

1. 找**动作词**（动词）——它在干嘛？
2. 找**对象**（`self.xxx` 忽略 self，看 xxx 是什么控件/变量）
3. 还在晕 → 先猜「用生活类比这是啥」，再查表验证。猜过一遍记得最牢。

自测：不看上面表格，用你的话讲「`loaded.connect(_on_loaded)` 这行在干嘛」——讲得出 = B 类通了；讲「为什么要三个 `_load_` 函数」——讲得出 = C 类通了。

## 4. 常见「看不懂」症状速查

| 症状 | 先查这里 |
|---|---|
| 看到 `xxx.yyy()` 不知道啥意思 | 拆：`xxx` 是对象，`yyy` 是它的动作（方法）；`()` 里是参数 |
| 括号里传函数，带不带括号？ | `connect(函数)` **不带**括号——传的是函数本身，不是调用结果 |
| `self.` 太多头晕 | 忽略它，先读后面：`self.label` 就是「那个标签控件」 |
| 大写开头的词（`QFileDialog`） | `Q` 开头 = Qt 库的类；`np.` = NumPy；`plt.` = pyplot |
| 双下划线 `__init__` | 类的构造函数，创建对象时自动调用，不用你手动叫 |
| 一个词查不到 | 先把大写拆开读（如 `getOpenFileName` → get/open/file/name），基本能猜中 |
